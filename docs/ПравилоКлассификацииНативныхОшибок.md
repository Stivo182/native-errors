# ПравилоКлассификацииНативныхОшибок

Описывает декларативное правило для
[`КлассификаторНативныхОшибок.ДобавитьПравила()`](КлассификаторНативныхОшибок.md).

Для обычного создания правила используйте
[`ФабрикаПравилНативныхОшибок`](ФабрикаПравилНативныхОшибок.md): она оставляет
в вызове только параметры выбранного способа сопоставления.

Текстовые поля принимают обычную строку или шаблон `НСтр`. Для шаблона
распознаются доступные русская и английская версии.

## Создание

```bsl
Новый ПравилоКлассификацииНативныхОшибок(
    <Способ>,
    <КодОшибки>,
    <Сообщение>,
    <НативныйТип = "">,
    <ШаблонСообщения = "">,
    <Префикс = "">,
    <Фрагмент = "">,
    <Окончание = "">,
    <Идентификатор = "">
)
```

## Пример

Если текст ошибки содержит изменяемые детали, используйте фрагмент вместе с
нативным типом:

```bsl
Классификатор = Новый КлассификаторНативныхОшибок;

Правила = Новый Массив;
Правила.Добавить(Новый ПравилоКлассификацииНативныхОшибок(
    СпособыСопоставленияНативныхОшибок.ТипИФрагмент(),
    "application.backend_unavailable",
    НСтр("ru = 'Сервер приложения недоступен'; en = 'Application server is unavailable'"),
    "System.Net.Sockets.SocketException",
    "",
    "",
    НСтр("ru = 'Отказано в подключении'; en = 'Connection refused'")
));

Классификатор.ДобавитьПравила(Правила);
```

`ТипИФрагмент()` требует, чтобы тип `System.Net.Sockets.SocketException` и
текстовый фрагмент находились в одном кадре ошибки. Поэтому общее выражение
`Connection refused` не сработает в ошибке другого типа.

## Параметры конструктора и поля

| Имя | Тип | Обязательный | Описание |
| --- | --- | --- | --- |
| Способ | Число | Да | Идентификатор из модуля [`СпособыСопоставленияНативныхОшибок`](СпособыСопоставленияНативныхОшибок.md). Определяет, какие поля участвуют в проверке. |
| КодОшибки | Строка | Да | Машинный код результата. Для пользовательского правила это может быть собственный стабильный код приложения; он не обязан входить в [`КодыНативныхОшибок`](КодыНативныхОшибок.md). |
| Сообщение | Строка | Да | Текст нормализованной ошибки. Сохраняется в её описании вместо исходного текста. |
| НативныйТип | Строка | Нет | Полное имя .NET-типа из внешнего исключения, например `System.IO.IOException`. Используется только способами с проверкой типа. |
| ШаблонСообщения | Строка | Нет | Полное сообщение для `Точное()`. |
| Префикс | Строка | Нет | Начальная часть сообщения для способов с префиксом. |
| Фрагмент | Строка | Нет | Часть сообщения, обязательная для способов с фрагментом. |
| Окончание | Строка | Нет | Завершающая часть сообщения для способов с окончанием. |
| Идентификатор | Строка | Нет | Внутренний идентификатор правила для поля `Правило` нормализованной ошибки. Если не задан, индекс создаёт его из источника и сквозного номера пользовательского правила. |

## Использование полей способами сопоставления

| Способ | НативныйТип | ШаблонСообщения | Префикс | Фрагмент | Окончание |
| --- | --- | --- | --- | --- | --- |
| `Точное()` | Не используется | Полное совпадение сообщения. | Не используется. | Не используется. | Не используется. |
| `Префикс()` | Не используется | Не используется. | Сообщение должно начинаться с значения. | Не используется. | Не используется. |
| `ПрефиксОкончание()` | Не используется | Не используется. | Сообщение должно начинаться с значения. | Не используется. | Сообщение должно оканчиваться значением. |
| `ПрефиксИФрагмент()` | Не используется | Не используется. | Сообщение должно начинаться с значения. | Сообщение должно содержать значение. | Не используется. |
| `ПоТипу()` | Точное совпадение типа. | Не используется. | Не используется. | Не используется. | Не используется. |
| `ТипИОкончание()` | Точное совпадение типа. | Не используется. | Не используется. | Не используется. | Сообщение должно оканчиваться значением. |
| `ТипИФрагмент()` | Точное совпадение типа. | Не используется. | Не используется. | Сообщение должно содержать значение. | Не используется. |
| `ТипИОбрамление()` | Точное совпадение типа. | Не используется. | Не используется. | Сообщение должно содержать значение. | Сообщение должно оканчиваться значением. |
